The problem

Bots drift. Silently.

Drift is invisible

A prompt edit lands in one language, not its twin. Nothing errors. The call just gets worse.

Found late, in bulk

Test at scale and dozens of issues surface at once — after a campaign is already waiting.

Each fix risks the next

Patch one section, break its neighbour. Re-verifying by hand costs more than the fix.

Net effect: manual testing is what blocks campaigns from going live.

Honesty

What it does not do

Backend faults

Bad inventory, API 5xx. Escalated, never "prompted around".

Model disobedience

Ignoring a clear instruction. More prose makes it worse.

Judgement calls

Tone and dignity still need a human ear.

Not every reported bug is a prompt bug. The rail is built to say "the inputs were wrong" out loud instead of editing.
The standard

Three tiers. All three, or it is not done.

1 · Did the bug die?

Reproduce the exact failure. Post-fix transcript or it does not count.

2 · Did anything else break?

Blast radius: the twin language, the shared logic, the tool payload.

3 · Has anything drifted?

Standing daily check across the whole fleet, unattended.

Tested on every variant — language, direction, backend. Never extrapolated.
The compounding asset

Why it compounds

Every bug fixed must teach the analyser. The catalogue only grows, so the same class is caught pre-flight next time — on a bot nobody has seen yet.

This is the moat. Anyone can write a prompt. Few have a taxonomy of how voice prompts fail in production.

The gap

The fix

It now reads the deploy manifest and raises a critical if any live bot goes unchecked. Proven by hiding one.

A quality system that can silently under-cover is worse than none. So it audits itself.
