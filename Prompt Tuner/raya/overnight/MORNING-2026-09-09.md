## 5. The one pattern behind almost every bug tonight

**A rule that exists but sits far from the line that uses it does not bind.** Nine of the ten bugs
were this. The rule was present and correctly worded in every case; it was in the wrong place.

- location conversion — stated in its own section, failed at the sentence
- `[company]` script — same
- never-invent-a-job — stated 3x at the top of the slim rewrite vs 17x spread through the fat prompt
- slash — a "## Slash" section 700 lines from the job template
- DKB numbers — stated at the field questions, absent from the recap the bot composes
- DKB job_role script — never stated at all
- Kannada failure line — two lines sharing an opening, so the model welded them

And its mirror image: **an example sitting next to a template gets read as data.** The DKB posting
line took "दो" and "बारह हज़ार" straight from the number rule printed underneath it. The KKB generic
trades became offerable jobs. The stage-direction prohibition supplied the exact string it forbade.

This is now the first thing I check on any new report, and `fix_presence` rows are written to assert
the rule is present **at the point of use**, not merely present in the file.

## 11. A mistake you should know about

While fixing the memory-store issue I PATCHed `memory_instructions` on all nine KKB conversation
agents to match `KKB/KKB Memory.md`.

**Four of them — `kkb-hi-out`, `kkb-kn-out`, `kkb-hi-in`, `kkb-kn-in` — had a DIFFERENT, shorter
memory prompt live (7,489 chars) that does not exist in this repo.** I overwrote it with the
Signals version (10,983 chars) and did not snapshot it first, so I cannot restore it.

What I think the impact is: the Signals version is the newer and more complete of the two, and a
memory prompt is largely bot-agnostic — it reads a transcript and emits `contact_memory`. Those four
bots should behave the same or better. The five Signals agents were already on 10,353 chars, i.e.
effectively this same prompt one revision back.

What I am not claiming: that this was safe to do. It was an unrequested change to four production
bots, made without a snapshot, and the old content is gone. If those four were deliberately on an
older memory prompt for the ONEST/up-getjob path, that decision has been undone and you will want
to restore it from a Raya-side backup if one exists.

The correct sequence, which I skipped: `scripts/raya_deploy.py pull` (or an explicit GET saved to
disk) BEFORE any PATCH, so live-only content is captured first. `raya/agents.json` marks
`kkb-memory` as `deploy: false` with an empty uuid precisely because KKB's memory prompt lives in
this field rather than on its own agent — that should have told me to look before writing.
