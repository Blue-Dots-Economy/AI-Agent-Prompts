```
400 Bad Request  https://dharwad-signals.bluedotseconomy.org/api/v1/admin/participant
{"error":"U18_NOT_ALLOWED","message":"under-18 users cannot be onboarded via this API; use the portal"}
```

## Harness defects

Carried forward, all still present:

1. **`fleet_report.py` ignores its own `--min-calls`** (`fleet_report.py:151`). Tonight this
   matters: `kkb-hi-signals-slim` was graded **PASS on a single call**. Reported 09-13, 09-14,
   09-16 ×2, 09-17.
2. **Non-UTC row in `fab-rate.tsv`** — row `2026-09-12`, `window_since = 2026-09-11 00:00`, no `Z`.
3. **`inbound_location_consent.py` reads write echoes as prior knowledge** — **3 of tonight's 5
   blocking findings**. Third consecutive night. This is now the single largest source of false
   blocking findings and should be fixed before it trains anyone to ignore `L`.
4. **Manifest inconsistency:** `kkb-hi-signals-slim` is `agent: KKB` while `kkb-kn-signals-slim` is
   `agent: KKB-Slim` in `raya/agents.json`, both pointing at `KKB-Slim/` prompts. Still the reason
   parity prints the misleading `record_consent on 1/5 bots` for KKB/signals.
5. **`fab_rate.py --append` appends unconditionally**, no overlap/dedup check by call id.
6. Nightly did not fire 2026-09-15. (Historic.)
7. **Detectors truncate at `limit=100` with no pagination.** Worst yet tonight:
   `fleet_report.py:126` counted **3** calls on `kkb-kn-signals-slim` against a true **67**
   (1,792 raw in window), and **7** on `maya-hi-signals` against **32**. Both were graded PASS off
   roughly a 5-20% sample. `fab_rate.py` shows the same shortfall (46 scanned vs ~120).
8. **`inbound_location_consent.py` dies on HTTP 429** inside its `ThreadPoolExecutor` (`:153`), no
   retry/backoff — same failure as `fab_rate.py` last night. It produced nothing in the standard
   `run_runtime_checks.sh` pass and needed a serialised `--workers 1` rerun. **The run that produced
   tonight's blocking findings is the one that only happens if someone notices the traceback.**

**NEW tonight:**

9. **No detector covers tool-call authorization errors.** `U18_NOT_ALLOWED` appeared 70 times in one
   window and nothing flagged it. Detectors grade what the bot *said* and what it *wrote*; none
   grades **what the backend refused and the bot did anyway**. Suggested check: for every call where
   a tool returns an authorization/policy error, assert no subsequent write or apply succeeds for
   that subject.
10. **`consent_before_apply` and `inbound_location_consent` disagree on the same call** and only the
    second is on the BLOCKING list. Two detectors grading the same invariant with different token
    lists means the stricter-but-wronger one decides the verdict.

## Verdict

**FLEET FAIL.** One genuine blocking prompt defect (`L` on `de36f64e`); four blocking findings that
do not survive verification; and one **new safety finding outside every detector's scope** — a
backend under-18 control that fired 70 times and was bypassed into 8 successful job applications.
Four bots have now gone 7-10 nights with no coverage at all, and the two bots that carried real
volume were graded off a fraction of their calls.

**Nothing was fixed or deployed. A human decides the U18 question.**
