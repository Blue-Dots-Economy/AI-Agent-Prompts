### `L OPEN ASK ON KNOWN PROFILE LOCATION` — maya-hi-in-signals, call `b09803dd-ad16-4887-86f1-27306043bc85` (2026-09-14T05:27:46Z)

Detector text: *"profile carried 'Ghaziabad, Uttar Pradesh, India' and the bot asked the open area
question anyway."*

**The bot behaved correctly. This is a harness bug, not a prompt bug.** Traced through the call:

| turn | what happened |
|---|---|
| 6 | `get_profile` called |
| 7 | result: **one** item, correctly `item_type: profile_1.0` / `item_domain: seeker`, `item_locations: []` — **no location at all**. The string `Ghaziabad` appears **0 times** in this result. |
| 10 | bot asks the open area question — **correct**, it held no location |
| 11 | caller answers: "मोदीनगर या गाजीबाद के एरिया में" |
| 21 | `create_profile` **result** carries `location: 'Ghaziabad, Uttar Pradesh, India'` — written *from* the caller's turn-11 answer |
| 29 | `update_profile` result carries `location: 'Modinagar, Ghaziabad, Uttar Pradesh, India'` |

Root cause is `raya/regression/inbound_location_consent.py`, `profile_location()`: it walks **every**
tool message whose body contains `user_id` and `profile_1.0` and returns the first
`'location': '...'` match. That sweeps in the `create_profile` / `update_profile` **write echoes**,
which are the location the bot just *learned from the open ask*. The detector then reports the bot
for re-asking a fact it "already held".

Two defects in one:
- **No temporal guard** — it must only consider profile state known *before* the open ask fires.
- **No source guard** — it must read `get_profile` results only, never a write echo.

Consequence: this will fire on essentially **every** inbound call where the caller states a location
and the bot correctly writes it — i.e. every successful inbound profile creation. The same wrongly
sourced `loc` also feeds the `M JOBS IN ANOTHER CITY` check on the same call.

Note the detector's own docstring case (`bbdb6eaf`, "Delhi, India", 2026-09-03) may still be genuine
— that profile carried a location on the `get_profile` result. This verification does not clear that
one; it clears tonight's.

**No fix applied — this run is read-only. A human decides.**
